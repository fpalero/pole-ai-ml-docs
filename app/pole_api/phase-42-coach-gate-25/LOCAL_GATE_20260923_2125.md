## Fail 1 — PR-02 / PR-04 systematic `md-first` violation (ROOT CAUSE FOUND)

Answers lead with `progress_matrix` instead of prose.

- **Mechanism:** `sanitize_blocks`
  (`app/pole_api/src/analyst_chatbot/blocks.py:898-904`) silently DROPS md
  blocks with empty/falsy content (`if isinstance(content, str) and content`).
  When the model emits leading empty prose, the strip promotes the matrix to
  `blocks[0]`. `ensure_tool_blocks` only ever appends, so it can't restore
  order.
- **Contract violated:** the documented block vocabulary
  (`coach-150q.spec.ts:92`) mandates md-first — the app violates its own
  contract on empty leading prose.
- **Diffed tickets 134/135/136 for ordering changes:** none (134 appends tier
  blocks in readiness-only functions).
- **Verdict:** model-nondeterminism-exposed contract hole, same family as ticket
  135's blanks but at block level.
- **Fix direction (NOT implemented):** enforce md-first structurally in shaping
  (prepend reply-md / reorder) + drop whitespace-only md.
