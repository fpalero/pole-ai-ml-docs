# Ticket: PAIML-POLE-ANALYST-064

## Title
[Features] Statistics tab redesign — spider/radar of the 5 metrics + metric legend + agent explanation

## Description
Phase 19 (PLAN_PHASE_19.md). Replace the histogram charts in the Statistics tab with the Stitch
target: a **spider/radar diagram of the 5 metrics** (per-metric 0–100 scores from the analysis
summary), below it a **legend describing what each metric means** (static FE dictionary, ES/EN per
user language), and an **explanation generated by the agent** reusing the persisted
`coach_summary` content (already available via AnalysisService; render summary/critical insight —
no new LLM call). Keep the existing Metric Distribution cards section beneath.

## What to Do (Implementation Steps)
- [ ] Radar component (standalone, SVG-based, no new deps): 5 axes = first 5 scored metrics
      (deterministic order), value polygon, scale rings 0/50/100, tooltips/values on axis ends.
- [ ] Static METRIC_DESCRIPTIONS dictionary in `models/statistics.ts` (+spec) for all known metric
      keys; unknown keys fall back to humanized key name without description.
- [ ] Agent explanation card: reuse persisted coach summary content (silent degradation to hidden
      when absent, mirroring existing patterns).
- [ ] Keep distribution-cards section; reorder panel: radar → legend → explanation → distributions.
- [ ] Unit specs: radar geometry helper (pure fn: scores→axis points), legend mapping, empty/partial
      scores handling; SummaryTab-free (component-level specs).

## Acceptance Criteria (Definition of Done for this Ticket)
- [ ] Statistics tab shows radar + descriptions + agent explanation per design intent.
- [ ] Histograms no longer primary content of this tab.
- [ ] Suite green; build clean; no leaks.

## Follow-ups (QA round 1 — iteration 2 fixes)

- **Orphan ownership (by design)**: `MetricChart`
  (`shared/components/metric-chart`), `MetricDetailModal`
  (`features/analysis/components/metric-detail-modal`) and
  `histogramDataFromDoc` (`features/analysis/models/histogram.ts`) lost
  their only consumer when this ticket replaced the histogram view with
  the radar. They are kept intentionally for now; **candidate cleanup
  ticket** to delete them (plus their specs) once phase 19 is confirmed
  stable.
- Radar draws ALL scored metrics as axes in the backend canonical order
  (team-lead decision): `orderMetrics` exported from `models/histogram.ts`
  and reused by `selectRadarScores`; legend derives from the same output.
- Axis-end labels are two-line (compact name over NN/100) and clamped into
  a ≥30%-padded viewBox via the pure fit model (`labelLayout` /
  `labelInkBox`); fitting is spec'd mathematically because jsdom lacks SVG
  geometry APIs.
- Optional follow-up (not done, low value vs risk): switchMap-style
  cancellation for the supplementary coach/distribution fetches — the
  existing `loadedSupplementaryFor` marker guard already drops stale
  responses and is covered by specs.
